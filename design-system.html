FDS — дизайн-система flowerdog

Из чего собран сайт flowerdog.studio и как его продолжать. Каждый пример на этой странице сделан теми же классами, что работают на сайте. Если страница и сайт разошлись, что-то сломано.

Код системы лежит в css/fds*.css, короткий свод правил для разработчиков и агентов — в docs/fds.md. Новое сначала появляется здесь, с примером и описанием, потом на странице сайта.

Правила

  1. Нет класса в системе — нет стиля на сайте. Всё, что видно на сайте, собрано из классов и токенов FDS.
  2. Исключений нет. Не бывает правил под конкретную страницу, клиента или кейс. Если компоненту нужно выглядеть иначе, у него появляется модификатор, и этот модификатор работает в любом месте сайта.
  3. Размеры называются как размеры одежды. У плашек, отступов, скруглений, обёрток и картинок есть шкала 2xs xs s m l xl. Класс без модификатора всегда M. Новый размер добавляется только по краям шкалы (3xs, 2xl), между существующими ступенями ничего не вставляется: нужно «чуть больше S» — значит, берём S или M.
  4. У текста своя лестница: H1, H2, H3, H4, текст, подпись. Внутри уровня размер один, меняется только вес: regular, medium, bold.
  5. Всё от базы. Размеры задаются в долях базы страницы, поэтому сайт масштабируется целиком и одинаково выглядит на любой ширине. Пиксели есть только в формуле базы.
  6. Всё называется по fds. Классы fds-, токены --fds-, файлы css/fds-*.css, элементы <fds-gallery>.

Файлы и имена

Страница подключает один файл, css/fds.css. Он объявляет каскадные слои и импортирует остальное, по файлу на компонент. Слой важнее специфичности: правило компонента всегда побеждает правило текста, поэтому селекторы короткие.

@layer tokens, base, layout, text, components, pages, utilities;

@import url("fds-tokens.css")     layer(tokens);      /* все значения */
@import url("fds-normalize.css")  layer(base);
@import url("fds-settings.css")   layer(base);        /* шрифт, база */
@import url("fds-transition.css") layer(base);        /* переход между страницами */
@import url("fds-layout.css")     layer(layout);      /* обёртки, спейсеры, сетка */
@import url("fds-text.css")       layer(text);        /* лестница текста и теги */
@import url("fds-link.css")       layer(text);
@import url("fds-chip.css")       layer(components);
@import url("fds-header.css")     layer(components);
@import url("fds-footer.css")     layer(components);

Имена

Схема одна: fds-блок__элемент--модификатор. Блок называется по смыслу, а не по странице и не по человеку. Модификатор отвечает на вопрос «какой?» по одной оси:

ОсьЗначенияПример
Размер2xs xs s m l xl, без модификатора Mfds-chip--s, fds-space--l, fds-wrap--l
Вес текстаregular medium boldfds-h2--medium, fds-caption--bold
Цветaccentfds-quote--accent
Формаhard soft roundfds-card__cover--round
Только на мобилеmobile- + размерfds-space--mobile-s

Состояния ставит скрипт, они без префикса: is-active, is-hidden, has-menu-open. Атрибуты data-* несут контент и поведение (data-ru, data-en, data-client-tag), стилей к ним не привязывают.

База и ширины

Шрифт Sona, variable 100..900, один файл fonts/Sona.woff2.

База — размер шрифта страницы. Она растёт вместе с шириной окна, а всё остальное задано в долях базы (rem, внутри компонентов em), поэтому страница масштабируется целиком, как плакат.

  • Телефоны: база растёт с 14px на 320px и останавливается на 20px (с 469px), чтобы планшет в мобильной раскладке не получал огромный текст.
  • Десктоп: от 11px на 768px до 22.5px на 1500px, дальше не растёт. Но меньше 14px база не бывает, поэтому планшеты и телефоны в горизонтали остаются читаемыми.
font-size: clamp(14px, calc(14px + 18 * (100vw - 320px) / 448), 20px);
@media (width > 768px) {
  font-size: clamp(14px, calc(11px + 11.5 * (100vw - 768px) / 732), 22.5px);
}

Раскладки две: мобила это width <= 768px, десктоп всё, что шире. В коде граница записывается только так:

@media (width <= 768px) { … }

Своя граница есть только у шапки: до 1024px она складывается в бургер, потому что меню не помещается рядом с логотипом.

Правила

  1. Тег выбирается по смыслу, вид — классом. На странице один h1. Название кейса — это h1, который выглядит как H2: <h1 class="fds-h2">. Голые h1–h4 выглядят как свой уровень.
  2. Вес задаётся модификатором уровня: --regular, --medium, --bold. Без модификатора заголовки bold, текст и подпись regular. Других весов нет.
  3. Компонент не придумывает размеры шрифта, он берёт токены лестницы: --fds-type-h1…--fds-type-caption, интерлиньяжи --fds-type-*-leading, веса --fds-weight-*.
  4. У заголовка нижний отступ по его уровню, у абзаца свой, каким бы стилем он ни был набран. Вертикальный ритм между блоками задают спейсеры.
  5. Неразрывные пробелы перед короткими словами расставляет js/nbsp-typography.js. В разметке &nbsp; только там, где скрипт не достаёт: внутри data-ru и data-en.
  6. Переносы строк, которые важны для смысла, задаются br. Перенос только для десктопа — fds-desktop-only.

.fds-grid — четыре колонки без зазора, --2 и --3 — две и три. Элемент занимает одну колонку, --l две, --xl все. Тултип

.fds-tip — синий блок со скруглением S и белым текстом 17em шириной. Появляется у слова .fds-term при наведении и исчезает за 0.5s. Варианты --wide (28em) и --aside (половина ширины, на мобиле по центру). Тексты лежат в js/quote-tooltip.js.

Камерная — значит небольшая: каждый проект ведут основатели.

Галерея кейса

Элемент <fds-gallery> (js/fds-gallery.js) раскладывает картинки figure.fds-figure в три колонки. --l занимает половину, --xl всю ширину. Мелкие картинки со скруглением S, крупные M. Внутри картинка, видео или iframe. Модификаторы картинки: --bordered тонкая рамка поверх, --logo логотип по центру с большими полями, --tight скругление XS. fds-gallery--tight делает XS все скругления на мобиле. Одиночная картинка вне галереи — figure.fds-figure--framed.

Видео в галерее играет без звука, когда попадает в экран (js/video-viewport-autoplay.js). У видео с data-sound-toggle на мобиле есть кнопка .fds-sound, на десктопе курсор-динамик.

Шапка кейса

Кейс начинается с обёртки fds-wrap--s с атрибутами data-type-tags и data-client-tag: из них js/project-meta-tags.js собирает плашки S перед h1. Мета-строка .fds-meta с номером и датой набрана подписью. В конце кейса кредиты p.fds-credits: ярлык, аватар, имя bold и роль приглушённым.

Движение

Пять длительностей и три кривые. Наведите на строку, чтобы увидеть.

ТокенЗначениеГдеЖивьём
--fds-duration-fast0.12sполоска обложек
--fds-duration-base0.2sнаведение, стрелки, мобильное меню
--fds-duration-slow0.3sуход шапки, уход страницы
--fds-duration-enter0.34sпоявление страницы
--fds-duration-lazy0.5sтултип
--fds-ease-outcubic-bezier(0.22, 1, 0.36, 1)появление
--fds-ease-incubic-bezier(0.4, 0, 0.2, 1)исчезновение
  1. Переход между страницами: тело уходит вверх на 0.25em и гаснет за 0.3s, новое приходит снизу за 0.34s (fds-transition.css, js/page-transition.js).
  2. Подвал: лист страницы поднимается над картинками на пружинах. Параметры пружин живут в js/footer-reveal.js. Родной скролл браузера никогда не подавляется.
  3. prefers-reduced-motion: reduce выключает переходы, анимации и плавный скролл.
  4. Наведение меняет только цвет и прозрачность. Ничего не увеличивается и не всплывает.
